Kaivor FP068.1 — Freedium live-check fixes (13 Nov 2026)
=========================================================

Follow-up to FP068, from the live smoke check run on the phone over SSH.
All three fixes were verified live before being made.

1. Washington Post Technology feed URL corrected (news_freshness.py)
   - Was:    https://feeds.washingtonpost.com/rss/technology  (HTTP 404)
   - Now:    https://feeds.washingtonpost.com/rss/business/technology
   - The corrected URL was verified live (HTTP 200, 8,911 bytes).

2. Feed fetch timeout raised 10s -> 20s (news_freshness.py)
   - New constant FEED_FETCH_TIMEOUT_SECONDS = 20.
   - Washington Post feeds take ~11s to respond (World 10.66s, Technology
     10.71s measured live), just over the old 10s timeout, so they timed out
     on every refresh. Fetches run in parallel, so one slow feed does not
     block the refresh.

3. Freedium Mirror fallback also retries on HTTP 403 (article_extractor.py)
   - extract_article_text() now retries through the mirror when the direct
     fetch fails with extraction_failed OR with HTTP 403 on a
     Freedium-supported domain. Other HTTP errors are still not retried
     (404: the article does not exist; 429: rate-limited).
   - The http_error result now carries "http_status" (the numeric code) so
     the retry decision reads the code instead of parsing the message.
   - Live evidence: FT refuses the direct fetch (HTTP 403) while the mirror
     serves the full article (75KB, <article> present), so the 403 retry
     unlocks FT. The Economist's mirror page carries no article text, so
     its quality gates still return the original 403 result — no harm.

Tests

- tests/test_freedium_feeds_fp068.py: Technology WaPo URL expectation updated.
