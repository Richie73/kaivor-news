FP069 — Secure the live app

Auth gate on the mutating API routes
- All POST/PUT/DELETE news API routes now require the shared PIN +
  signed-session gate: /api/set_key, /api/add_feed, /api/save,
  /api/save/<id>, /api/refresh, /api/finance/refresh, /api/ai_brief,
  /api/ask_ai, /api/story_timeline, /api/story_intelligence,
  /api/why_matters, and PUT /api/relevance_profile.
- The gate reuses the Reading section's PIN pattern (new shared module
  app_security.py; reading_web.py now imports from it, behaviour
  unchanged). One unlock via the Reading section covers both Reading and
  the news mutations — one PIN, one session, no second mechanism.
- When the PIN/secret are not configured, mutating routes answer 503 with
  a clear "locked until configured" message naming the two variables.
  When configured but the session is not unlocked, they answer 401
  telling the user to unlock via the Reading section. Nothing fails
  silently.
- GET routes stay open for the PWA. /api/cron/refresh keeps its own
  bearer-token check and is deliberately not covered by this gate.
- Template: the Settings section now notes that saving keys and sources
  needs the app unlocked via the Reading tab; the save button and the
  market refresh now surface the server's error message instead of
  failing silently.

Exposed key purged
- A live-format OpenRouter key was present in 5 stale copies of
  config/local_config.py (releases/0.4.2-alpha_20260702_140025,
  releases/0.4.2-alpha_20260702_143945, Kaivor/, and the two
  Kaivor/releases/ copies). All five copies held the same key. Each
  file's key value was replaced with the empty value, matching the live
  root config/local_config.py. Verified by pattern only: no key value
  was printed, copied or recorded anywhere.
- Purging the files does NOT revoke the key. The key must still be
  revoked/rotated at OpenRouter (Richie's action). The live app reads
  its key from environment variables / the private store, not from
  these files, so rotation breaks nothing.
- Install-time find (13 Nov 2026): the phone's live tree held 7 MORE
  copies of the same key in backups/20260702_*/config/local_config.py
  (old backups, never in the snapshot because backups/ is excluded
  from it). All 7 were purged the same way during the FP069 install
  (key value replaced with the empty value; backup files kept).
  After the purge, the only sk-or-v1- match left in the phone tree is
  config/news_secrets.json — the sanctioned device secret store.
